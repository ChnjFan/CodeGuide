## 常见问题

### `push_back` 和 `emplace_back` 的区别

`push_back` 内部是先构造一个临时对象，再将临时对象拷贝/移动到容器内存，最后销毁临时对象。而 `emplace_back` 直接在容器分配的内存里原地构造对象，不产生临时对象。

GCC libstdc++ 在 **C++17 / GCC11+** 之后将 `push_back` 的调用转发到 `emplace_back` 统一直接在内存里构造对象。

### vector 与 list 核心区别

- **vector**：连续动态数组，内存地址连续，一块整块内存。可以随机访问，缓存命中率高，访问效率极高。插入元素可能需要扩容，GCC 按照 2 倍扩容，如果 2 倍不够按照实际需要的内存扩容，来平衡插入元素的效率，但是扩容可能会导致迭代器失效，这也是 vector 容易犯错的地方。
- **list**：双向循环链表，节点分散存储，每个节点存数据 + 前后指针，内存不连续。只能顺序遍历，缓存命中率低，访问效率差。插入/删除元素只需要修改节点指针，且不影响其他迭代器。

**使用场景：**

C++ Core Guidelines 中强调能使用 `vector` 就应该使用，主要原因是现代 CPU 的速度远快于内存，依靠缓存行和空间局部性，绝大多数场景综合性能 `vector` 要比 `list` 快好几倍。

但是在一些需要迭代器稳定的任务队列、超大对象频繁的在中间插入删除等场景仍然使用 `list`。
